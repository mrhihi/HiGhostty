# 主視窗位置與大小

設定頁「視窗」有兩個模式：**螢幕置中**（預設）與**記住上次位置**。兩者的大小與位置都依螢幕各記一份。

## 設計

- 座標一律是 AppKit points（原點左下，所有螢幕共用一個座標系，不受各螢幕 scale 影響）。
  不可用 Tauri 的 physical 座標：macOS 上它是「points × 視窗目前所在螢幕的 scale」，Retina＋外接螢幕混用時不連續。
- `native/window.m` 的 `hg_window`（主執行緒）提供 `screens`／`frame`／`set-frame`；純計算在 `src/window_layout.rs`。
- 啟動：主視窗 `visible: false` 建立 → `apply_startup_layout` 算出目標外框、一次 `setFrame` → `show()` → `LAYOUT_READY`。
  分多步設定或先以預設大小顯示，AppKit 會把大小夾到當時螢幕的可視範圍，而且中間事件會被存回去。
- 儲存：Moved／Resized 去抖 500ms 後，在主執行緒讀 `frame`；全螢幕與最小化不存；縮放（雙擊標題列、拉滿螢幕）要存，否則記住的會永遠停在拉滿之前的寬度。
- 目標螢幕：置中＝滑鼠所在螢幕（否則主螢幕）；記住＝上次所在螢幕，已拔除則退回滑鼠所在螢幕。最後一律夾進該螢幕的可視範圍。

## `window-state.json`

```json
{
  "placement": "center",
  "last_screen": "<vendor-model-serial@寬x高>",
  "screens": { "<key>": { "left": 100, "top": 40, "width": 1500, "height": 900 } }
}
```

`left`／`top` 相對該螢幕可視範圍的左上角。舊格式的頂層 `width`／`height`／`x`／`y` 不再使用（沒有該螢幕紀錄時用預設 1280×820 置中）。

## 驗收清單

debug 與 release 都要做。

1. 單螢幕：兩種模式各重開 3 次，大小不漂移、不往下滑。
2. Retina 筆電＋1x 外接：視窗放外接並調大小，記住模式重開 → 同螢幕同位置同大小；拖到筆電調小重開 → 在筆電；再拖回外接 → 外接大小仍是原本的。
3. 置中：游標放在另一個螢幕再開 App → 在該螢幕可視範圍置中，大小為該螢幕的紀錄。
4. 記住模式後拔掉外接螢幕再開 → 落在游標所在螢幕且完整可見。
5. 拉滿螢幕（拖邊框或雙擊標題列）後重開 → 仍然滿版；進入全螢幕後結束再開 → 不把全螢幕尺寸存成一般大小。
6. 啟動時不會先在主螢幕閃一下預設大小。
